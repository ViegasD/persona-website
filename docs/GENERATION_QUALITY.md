# Character references and generation settings

The raw xAI REST request must use `image: {"url": ...}`. `image_url` is an SDK argument, not the REST input field. Catalog originals are fitted, without cropping or generative editing, onto a white 720×1280 canvas. xAI receives that image as a data URI. The worker logs its SHA-256 fingerprint and provider request ID, never its encoded contents.

Prompts preserve the source appearance, scene, pose and viewing angle. Animation is limited to lip sync, blinking and subtle expressions. Multi-character composites retain ordered cast positions; cache keys include input fingerprints, model and prompt version. Existing cache rows are preserved but obsolete keys are no longer selected.

The script writer uses a shared speech budget of two words per second with a two-second finishing margin. Oversized dialogue is rewritten up to three times; persistent failure stops before submitting a billable video instead of substituting generic dialogue. Generated video duration is checked with ffprobe before publication. Identity still needs visual review when investigating a quality complaint; these safeguards cannot guarantee perfect generative output.

## Administrator controls

Settings → Loja, contas e créditos contains duration and model overrides. Duration accepts integer seconds from 4 to 15. Blank values inherit `XAI_VIDEO_DURATION_SECONDS` and `XAI_VIDEO_MODEL` from the backend environment. The worker reads database overrides for each new generation, so saving does not require a restart. In-flight jobs retain the configuration snapshot they started with. Existing orders and videos are not regenerated by a settings change.

Supported model overrides are `grok-imagine-video` and `grok-imagine-video-1.5`; switching is an operator decision and does not automatically regenerate orders. Resolution is selected by the purchased quality: SD 480p, HD 720p. Cost logs are estimates using configured per-second rates; update those rates when provider pricing/model changes.

Migration `0015_generation_settings` adds nullable settings columns only. Back up the database before deployment. Preserve the existing historical processing cutoff, isolated new-order queue, and disabled recovery setting.

## Confirmed reference-failure repair

`scripts/repair_reference_videos.py` is restricted to the five confirmed affected items from orders 175–177 on 2026-10-26. It does not scan or enqueue a historical backlog.

Run it as a module with a private durable mounted directory:

```sh
python -m scripts.repair_reference_videos prepare --state-dir /private/repair-state
python -m scripts.repair_reference_videos generate --state-dir /private/repair-state
python -m scripts.repair_reference_videos review --state-dir /private/repair-state
# Review the generated contact sheet and videos before continuing.
python -m scripts.repair_reference_videos publish --state-dir /private/repair-state
python -m scripts.repair_reference_videos notify --state-dir /private/repair-state
```

State contains customer information and must never be committed. New videos use distinct storage keys; old objects and metadata remain in the private repair manifest. Publication atomically changes only the five item video/thumbnail/prompt/request pointers. Payments, credit balances, order statuses, and historical queue records are untouched. An ambiguous generation submission or SMTP delivery blocks automatic resubmission; inspect the provider before taking further action. SMTP acceptance is recorded separately from confirmed inbox delivery.

Account owners can access their replacements normally. A verified account email can also read unowned guest orders matching that email; unverified accounts, other mailboxes, and orders already owned by another account are excluded. This read-only association does not rewrite historical guest-order ownership and does not grant edit or checkout permissions.
