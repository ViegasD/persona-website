# Contextual scenes

New scenes use the existing single image-generation step followed by the existing single video-generation step. This release does not switch models, change the configured duration, add shots, change speech budgets or introduce camera/body movement. The live admin policy controls the duration and video model.

`scene_builder.scene_context` maps the occasion to a curated setting and visible props. Birthdays have a cake, balloon arch, gifts and unlettered bunting. Other settings cover Christmas, reassurance, achievement, graduation, family occasions, weddings, affection and general greetings. Messages can select supported visual themes: football, space, ocean, dinosaurs and reading. These are deterministic keyword selections, not unrestricted interpretation of arbitrary customer instructions. Negated interests are ignored conservatively. Customer names, ages and raw messages are never interpolated into the image prompt.

Keep the original character's identity and anatomy. Place props on tables or in the scenery rather than inventing hands or replacing existing accessories. Scenes have coordinated colors, foreground/background depth and visible occasion details. Generated text, names and age numbers are excluded; personalized typography remains future work.

The background-only cutout fallback uses the same contextual setting and props. Its original character pixels are preserved, with space around the character for scenery. The existing review now also checks occasion suitability before a contextual scene can enter the cache or reach video generation. A failed review stops processing; this release does not add automatic paid retries.

Cache version `occasion-scene-v5` separates richer scenes from previous cached images. Keys include character order, reference fingerprints, image model, recipient, occasion and selected visual context. Equivalent theme selections reuse the same visual context; changing a supported theme cannot return a scene from another theme. Approved existing scenes attached to in-flight orders are retained. No historical media, orders or cached objects are deleted or regenerated by deployment.

Validation uses mocked providers and tests context selection, negation, prompt isolation, main/fallback scenery, review gating and cache separation. No paid generation or customer delivery is part of release QA. Real output quality, including the actual 15-second result, still requires a separately authorized provider test.
